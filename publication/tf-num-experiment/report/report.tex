\section{Overview}
This report analyses the 14 completed runs of the publication TF-count experiment. The number of TFs was swept from 200 to 2,800 in steps of 200 while the GRN parameter $k$ was held fixed at 15. Results are indexed by the number of \emph{target genes} in the causal graph, as requested. Logs are taken from Slurm job \texttt{35274208}, which matches the current \texttt{results/} directory. The older sweep (job \texttt{33898186}/\texttt{33898382}, sizes 100 to 2,900) and \texttt{results-old/} are excluded.
\paragraph{Requested versus realised TFs.} The sweep requests a number of TFs, but the causal graph that is actually trained on retains a different number once the bipartite filtering removes TFs that regulate only other selected TFs. The realised count matches the request up to 1,200 TFs, is nearly equal at 1,400 and 1,600, and then falls below it (1,155 realised for 2,800 requested). This report uses the \emph{realised} counts from the causal-graph block of each log, and Table~\ref{tab:grn} lists both.
\paragraph{Genes discarded and the fit subset.} The dataset has 3,000 genes. As the TF count grows, some genes are discarded from the causal graph; the number discarded is listed in Table~\ref{tab:grn}. Runs with fewer than 100 genes discarded (requested TFs 200--1800, 9 runs) form a \emph{fit subset}. Beyond that, discarding grows quickly, so the subset fit tests whether the discarding is what drives the scaling.
\paragraph{Missing run.} There is no 3,000-TF run in either \texttt{results/} or the logs. With 3,000 genes in the dataset, 3,000 TFs would leave no target genes, which is the likely reason it was not formed; no log confirms this directly.

\section{Notes}
\begin{itemize}
\item Fit subset: the 9 runs with fewer than 100 genes discarded (largest discard in the subset: 61; smallest discard among excluded runs: 156). Comparing the subset line with the all-run line: parameters: slope -0.9\%, subset line misses excluded runs by up to 11.2\%; peak memory: slope -11.6\%, subset line misses excluded runs by up to 3.9\%; step time: slope +8.2\%, subset line misses excluded runs by up to 25.6\%. The subset covers a narrower target range (1,200 to 2,800), so these slope changes carry more uncertainty than the R\textsuperscript{2} values.
\item Scope of each input. Generator parameters are \texttt{gen\_state\_dict} minus the controller's parameters, so they describe the causal generator alone. Optimiser counts are already generator-only: the generator optimiser holds about three times the sparse-generator parameter count, far below what it would be if the controller were included. Peak GPU memory is the maximum inside the generator-training window, which starts after the controller window closes. The controller's resident weights are about 14 MiB, under 0.2\% of the generator peak. Step time is the generator-phase step logged by the trainer; the causal generator's forward pass calls the controller, so that time is not separable from the logs.
\item TF/Target exceeds 100\% from 1{,}600 requested TFs onward, meaning the graph has more TFs than target genes; the ratio is reported as a plain percentage for consistency with the other experiments.
\item Imposed edges fall from 41{,}610 to 3{,}000 across the sweep, and the generator's parameter count falls with them. Target genes therefore track the sparse-edge budget as well as the output dimension, so the fits in $T$ describe this sweep rather than a pure dependence on target count.
\item Runs with an out-of-memory error: 0 of 14.
\end{itemize}
